# Donor Fit Map

## Accepted From Donor Pattern

- Monorepo as the central operating surface
- Separate packages for kernel, intake, memory-facing projections, and operator surfaces
- Nx as the orchestration harness

## Explicit Non-Transfers

- No direct donor tarball import into `entif-ai`
- No donor ontology promoted over Rosetta
- No donor memory stack replacing the constitutional cache or receipt bundle logic

## Working Rule

The donor is treated like a reference skeleton in anatomy class: useful for proportion and placement, but not the living body we are constructing here.
