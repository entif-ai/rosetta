## Summary
This RFC establishes the unified architectural doctrine tying together Rosetta v3 (semantic constitution), OMOC (Ontological Mixture of Concepts — a routing-and-specialization doctrine that replaces static expert personas with task-local concept simplexes assembled from faceted taxonomy), and Swarm Gnosis (a staged federated exchange layer for content-addressed cognitive tiles, tapestries, and signed attestations). It codifies six governing invariants (sovereign semantics, receipts-first, signal/semantics separation, non-collapse of uncertainty, compiled context, explicit ontology declaration, forecast-before-action, epistemic build sequencing), defines a six-layer architectural model (Constitution → Taxonomy → OMOC → Memory → Runtime → Compute/Federation), proposes eight data contracts for formalization, specifies an eight-tack build order, and flags eight open research questions. The MR TECH LEAD model-stack ideology is explicitly subordinated to Rosetta semantics.

## Goals And Intent
- Keep Rosetta v3 as the invariant semantic and provenance spine; do not redefine it.
- Introduce OMOC as the routing doctrine: compile task-specific concept tranches (Foundational / Domain / Intersection / Problem / Execution) into a simplex rather than invoking static expert personas.
- Formalize Swarm Gnosis as the federated exchange layer for verified tiles, tapestries, profiles, operators, and cognitive artifacts — proceeding in staged layers from single-tenant to public commons.
- Integrate MR TECH LEAD model-stack ideology without letting compute innovations bloat the semantic constitution; components stay in separate lanes (Rosetta / Draft-and-Prune / H-Neurons / ELIXIR / ENGRAM / AttnRes / Mamba / TurboQuant).
- Align the system with standards-oriented taxonomy, explicit epistemics, receipts-first governance, and buildable execution order (epistemic sequencing).
- Produce a companion spec suite: 7 ROCK specs (ROCK-3201 through ROCK-3207) and 1 implementation playbook (ENTIF-OMOC-001).

- **AttnRes / CCA** — selective depth routing; cheaper exact/global attention; model architecture lane

- **TurboQuant** — vector and cache compression; systems and infrastructure lane
- **SKOS** — lightweight concept schemes, broader/narrower relationships
- **SHACL** — profile validation and graph-shape constraints
- **OWL 2 / RDF/RDFS** — class/property semantics, inference, graph export
- **PROV-O** — interoperable provenance projection
- **BPMN / DMN / SCXML** — process and decision modeling
- **OpenAPI / AsyncAPI / CloudEvents** — interface and event descriptions
- **OpenTelemetry Semantic Conventions** — observability naming
- **NERDm-style JSON Schema + JSON-LD** — metadata envelopes for datasets, software, services, portals, tools, resource bundles
- **Semantic gauge blocks** — calibration corpora, alignment exemplars, canonical semantic fixtures for cross-model and cross-lab calibration

## Conceptual Claims
- **Claim 1**: The next useful generation of agentic systems will be won by semantic sovereignty, provenance discipline, concept-native routing, governed memory, and layered compute specialization — not by larger prompts, broader personas, more autonomous loops, or a noisier MoE bazaar.
- **Claim 2**: Rosetta v3 already establishes the correct constitutional posture (minimal, stable, extensible core spine; content-addressed tiles; universal operational trace; separation of signals from semantics; explicit uncertainty; pack-based interoperability).
- **Claim 3**: OMOC replaces static persona libraries and conventional MoE framing with ontological mixtures of concepts — routing on conceptual structure rather than role costume.
- **Claim 4**: Swarm Gnosis turns the tile-first posture into a federated knowledge substrate; the atomic object is content-addressed cognitive tile; the exchange object is tapestry.
- **Claim 5**: MR TECH LEAD model-stack innovations each solve different dirty jobs and must not become one sacred block; none are allowed to redefine semantic identity.
- **Claim 6**: Shared understanding does NOT emerge from hoping latent manifolds converge across vendors — it emerges from canonical semantic objects, explicit mapping layers, typed ambiguity, stable references, and verifiable evidence chains.
- **Claim 7**: The strongest pairing in the architecture is Rosetta + ENGRAM: Rosetta provides deterministic semantic keys and canonical objects; conditional memory provides cheap runtime access to reusable structures.
- **Claim 8**: The right federation order is staged (single-tenant → multi-agent local → org-scoped → trusted inter-org → public commons); do not begin with a fully public global swarm.
- **Claim 9**: Human delegates belong in the swarm switchboard; preventing "automation purity" as an optimization target is a design principle.
- **Claim 10**: AttnRes and related innovations do not solve the meaning problem; better internal routing makes models smarter or cheaper — it does not make semantic identity, provenance, and interoperability disappear.
- **Claim 11**: Build order must follow epistemic sequencing — a work package is valid only when it resolves a prioritized uncertainty, produces diagnostic evidence, and unlocks a next decision.
- **Claim 12**: Rights-scoped retrieval means do not retrieve everything and filter later; the system must retrieve under scope; this is essential for privacy, multi-tenancy, selective disclosure, cache-domain hygiene, and swarm publication safety.
- **Claim 13**: Parse-only by default; ambient/broad ingest must remain parse-only; side effects require explicit command mode, guard passage, and receipts.

## Dependencies And Sequencing
- **Tack 0** (prove semantic kernel): requires Rosetta v3.0.0 Core Spine + ROCK-31XX receipts. Gate: zero-trust verification on one vertical slice.
- **Tack 1** (context compiler + stable bands): requires Tack 0 complete. Gate: measurable cache-hit improvement on repeated tasks.

## Contradictions Or Supersession
- **Contradiction A**: OMOC proposes concept tranches (Foundational/Domain/Intersection/Problem/Execution) as routing substrate, but §18 OQ-1 explicitly leaves unresolved whether routing is deterministic or learned. The Utility function in §8.4 has parameterized weights (aN, aR, aV, aS, aC, aK) — provenance of these weights is unspecified. This is an open architectural tension, not a contradiction.
- **Contradiction B**: The document argues for SKOS+SHACL facet-based classification (§6.1) while also referencing a "metacognitive atlas" with tulpamancy archetypes (§8.6/I12) — the latter uses calibrated regions over concept factors, which could be represented in SKOS but would benefit from a distinct schema. No conflict — just two representations of the same underlying structure.
- **Supersession**: Prior drafts of Entif memory architecture described "Prism" as potentially co-equal with Rosetta. This document explicitly subordinates all memory engines (Prism, Muninn, Engram) as runtime realizations under Rosetta's semantic constitution. This supersedes any prior claim of memory-engine parity with Rosetta.
- **Clarification**: The document does NOT redefine Rosetta core semantics — it explicitly preserves them (§1.3 non-goals, §3.1). All extensions are via packs, profiles, and runtime adapters.
