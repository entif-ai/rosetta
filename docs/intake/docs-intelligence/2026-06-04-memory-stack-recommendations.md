## Components And Technologies

- **MuninnDB**: cognitive database with Hebbian engram scoring, REST/gRPC/MCP endpoints, one binary, BSL 1.1
- **OB1 (OpenBrain)**: capture-and-recall facade for cross-client memory portability
- **Graphiti**: temporally-aware open-source KG framework (Zep open-source alternative)
- **AutoResearch**: bounded self-improvement loop targeting measurable KPI targets
- **Paperclip**: control plane for task governance, scheduling, heartbeats, budgets, approvals
- **ACP/acpx**: Agent Client Protocol, structured worker bus for typed agent communication
- **OpenSpec**: brownfield-first spec/change framework with living truth + explicit deltas
- **SpecKit**: feature-level spec generation grammar (GitHub-maintained MIT)
- **BMAD**: scale-adaptive planning with 12 specialized agents, document sharding
- **Claude Code plan mode**: session-level worker-local planning brake
- **GasTown**: multi-agent workspace coordination fabric (not spec framework)
- **DeerFlow**: deep-research framework built on LangGraph (research harness, not cognitive OS)
- **OpenEvolve**: evolutionary search for bounded evaluator optimization
- **S-Path-RAG (arXiv 2603.23512)**: semantic-aware path retrieval for multi-hop KGQA with NSGD loop
- **Weak-to-strong generalization**: multi-pass summary pipeline (weak/strong/verifier/promotion)

## Conceptual Claims

- Memory system should be cognitive metabolism, not RAG pipeline — distinct artifact species per stage
- Frame resolution must precede ingest to determine interpretation canon
- MuninnDB (hippocampus) + OB1 (mouth) + Graphiti (connective tissue) + AutoResearch (gym) is the recommended memory stack
- OB1 is capture facade, not canonical truth store; Entif should be disciplined substrate under it
- Three membranes: governance (Paperclip), worker specialization, memory/retrieval (Muninn + sidecars)
- Spec frameworks are change-frameworks, not PRD compilers; custom PRD compiler layer is required
- Work packets need three-band constraint model: hard constraints / design intent / freedom zone
- Four chunking units: Capability (A) / Change package (B) / Worker brief (C) / Atomic task (D)
- Scoring is multi-dimensional vector, not single scalar
- Storage is five layers: source archive / working interpretations / evaluated knowledge / agent-specific / shared canon
- Correlation is three-pass: cheap local / graph-path / dialogic NSGD-like refinement
- "Appropriate" is explicit routing decision per item to destination layer/actor/context
- Iteration has three modes: immediate / deferred consolidation / dreaming (read-only on canon)
- Dreaming must not directly mutate canon; emits candidates for review or low-risk adoption
- Weak-to-strong summary tiers: weak pass / strong pass / verifier pass / promotion pass
- Artifact species taxonomy prevents semantic mush: Observation, Interpretation, Claim, Hypothesis, Evaluation, Heuristic, Procedure, Synthesis, Decision, Ticket, Reflection

## Dependencies And Sequencing

- MuninnDB must be installed and running before OB1 and Graphiti sidecars can write shadows to it
- Paperclip control plane must be configured before coding workers (Claude Code, Gemini CLI, OpenCode) can be dispatched
- ACP/acpx must be configured as the typed bus before multi-agent coordination is possible
- OpenSpec repository structure must be initialized before PRD compiler can emit change packages
- PRD compiler layer (custom) is the gap between large PRDs and bounded work packets — it is the critical path item
- Five-layer storage model must be implemented before appropriation routing can function
- Artifact species taxonomy must be defined before stages can emit correctly-typed outputs
- S-Path-RAG/NSGD is referenced for correlate design but not yet implemented
