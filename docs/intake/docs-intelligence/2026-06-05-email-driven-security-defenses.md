## Summary

This document is a threat-modeling and defensive-architecture conversation that covers email-driven prompt injection at unusual depth. It is directly relevant to Rosetta's write-admission gate (NOT LAME), the skillpack importer quarantine flow, and any future connector adapter that handles inbound untrusted content. The most architecturally significant finding is that a policy engine external to the LLM — not the LLM itself — must be the authorization authority. Second most significant: taint propagation from email-derived content must survive summarization and persist all the way through the pipeline.

## Conceptual Claims

1. **Capability containment is the primary control.** Not "can the attacker inject text?" but "what can the agent do with text?" If the agent can call tools, memory writes, or external fetches, email-derived content reaching it is dangerous even with a clean parser.

2. **LLMs extract; policy engines decide.** The LLM is a good interpreter of email content but a poor authorization authority. Authorization must live outside the model.

3. **Taint is not removed by summarization.** A summary of hostile content is still hostile-derived. Taint propagates across stages unless explicitly stripped by policy.

4. **Provenance is necessary but not sufficient.** GPG signatures authenticate that a message came from a specific key; they do not authenticate that the content is safe or that the action is authorized.

5. **Ensemble diversity beats single-detector accuracy.** Bayesian + linear models + embedding classifiers + anomaly detectors each cover different failure modes. Combining them is more robust than trusting any one.

6. **Structured machine-state is safer than narrative text as downstream output.** Passing typed features/labels/bounds to downstream agents prevents the scoring layer from becoming an injection surface.
