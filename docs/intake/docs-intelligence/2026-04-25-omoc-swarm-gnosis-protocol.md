## Summary

This RFC synthesizes the strongest existing Entif/Rosetta artifacts into a unified architectural doctrine: **Rosetta** as sovereign semantic constitution, **OMOC** as routing law (concept mixtures vs static experts), **Swarm Gnosis** as federated exchange layer (content-addressed tiles, tapestries, signed artifacts), and **MR TECH LEAD** as compute ideology subordinate to Rosetta semantics. The document also specifies a 6-layer model, 8 governing invariants, 7-tack build order (Tack 0 through Tack 7), 6 new data contracts, 8 proposed ROCK companion specs, and 8 open research questions. It resolves several earlier tensions: MoE vs concept routing, property graph vs knowledge graph roles, compute vs constitution, and build-order priority. Findings confirm OMOC+Rosetta as a coherent thesis, Swarm Gnosis as the federation layer, and MR TECH LEAD as a compute layer with defined boundaries.

## Goals And Intent

- Keep Rosetta v3 as the invariant semantic and provenance spine.
- Introduce OMOC as the routing and specialization doctrine (mixtures of concepts, not static experts).
- Formalize Swarm Gnosis as the distributed exchange layer for verified cognitive artifacts.
- Integrate MR TECH LEAD model-stack ideology without letting compute innovations bloat the semantic constitution.
- Align with standards-oriented taxonomy, explicit epistemics, receipts-first governance, and buildable execution order.
- Produce a refinement-and-extension doctrine, not a core rewrite.
- Resolve prior tensions: MoE vs concept routing, property graph roles, compute vs constitution, federation build order.
- Identify open research questions rather than collapsing them prematurely.

## Conceptual Claims

1. **Layered sovereignty**: Rosetta is the semantic constitution; all other layers (OMOC routing, memory engines, compute strata, federation) are subordinate adapters and must not redefine core meanings. New capability arrives through packs, profiles, and runtime adapters, not core mutation.

2. **Concept composition over expert identity**: The routing primitive should be conceptual composition (what conceptual basis set is present in this task?) rather than expert identity (which expert do I wake up?). OMOC assembles concept tranches into task-local simplexes that may be implemented by models, tools, human operators, rule engines, or compiled procedures.

3. **Receipts as execution truth**: Every meaningful transformation must emit a receipt. Absence of receipt = failure condition, not optional logging.

4. **Non-collapse of uncertainty**: Ambiguity, conflict, multi-hypothesis state, and epistemic scope must remain first-class. The system should preserve conjecture distributions until sufficient evidence to collapse them.

5. **Survivorship over local utility**: Concepts/tiles/delegates that score poorly in one context should not be erased — they should be demoted to colder tiers. Only low Utility AND low Survivorship justifies pruning.

6. **Common understanding via gauge blocks, not embedding consensus**: Shared understanding emerges from canonical semantic objects, explicit mapping layers, typed ambiguity, stable references, and verifiable evidence chains — not from latent manifold convergence across vendors.

7. **Staged federation**: Public commons is the end state, not the starting point. Federation proceeds through five layers with increasing proof, rights, and abuse-handling requirements.

8. **Compute is subordinate to constitution**: MR TECH LEAD innovations solve different dirty jobs and must not become one sacred block. Better internal routing makes models smarter/cheaper; it does not solve the meaning problem.

9. **Memory as subordinate runtime**: Prism, Muninn, Engram, property graphs, and vector indexes are memory engines and runtime realizations under Rosetta constitution — not competing ontologies.

10. **Build order follows epistemic sequencing**: Each tack is valid only when it resolves a prioritized uncertainty, produces diagnostic evidence, and unlocks a next decision.

## Contradictions Or Supersession

- **MoE vs concept routing**: This document explicitly supersedes naive MoE framing by replacing expert identity routing with OMOC concept composition. Prior work that assumed static persona/expert libraries is superseded for routing decisions.
- **Property graphs vs knowledge graphs**: Prior discussions may have treated property graphs as either competing with or inferior to knowledge graphs. This document clarifies they serve different roles: property graphs = high-performance traversal views (not the constitution); Rosetta + standards = sovereign identity and provenance. No actual contradiction, but需要一个 explicit role clarification that was missing in earlier docs.
- **MR TECH LEAD as constitution vs compute ideology**: Earlier MR TECH LEAD framing may have implied the compute stack is the primary architectural contribution. This document explicitly subordinates MR TECH LEAD to Rosetta semantics — it is the compute ideology, not the constitution.
- **Memory engine roles**: Prior Entif memory documentation may have implied Prism or Muninn are co-equal with Rosetta. This document makes explicit: Rosetta is the constitution; Prism/Muninn/Engram are subordinate memory engines and runtime realizations.
