## Summary

This document is the primary architecture blueprint and phased roadmap for Entif.ai 2.0. It specifies a seven-layer cognitive architecture spanning from a universal representational layer (Entif Glyph Code / pasigraphy) through voice-first ingestion, orchestration (Ada), multi-timescale autobiographical memory (GraphRAG + Neo4j + Pasigraphy), hierarchical reasoning (TRMs + LLM Reasoner + ROMA planner), skill modules (Sony/Blink/Browser), and a full self-improvement stack (ELIXIR loop, Petri sandbox, Tripwire guards, EntAffirm oracle). It is grounded in fourteen-plus external AI research papers (Nested Learning, Titans, DeepSeek-OCR, MLACS, SEAL, MONA, etc.) mapped to Entif components. The roadmap spans Phase 0 (Foundation) through Phase 5+ with detailed sub-phases for Semantic Grounding and Interactive Orchestration.

## Goals And Intent

- Specify a complete cognitive architecture for a personal AI companion with persistent memory, semantic understanding, autonomous coding, and self-improvement
- Provide a thin-slice phased roadmap executable by a solo developer with LLM support
- Ground architectural decisions in peer-reviewed AI research
- Establish receipts-first telemetry as the universal currency of the system
- Define safety/alignment mechanisms (EntAffirm, Petri, Tripwire, Genesis Anchor) as first-class architecture, not afterthoughts

## Components And Technologies

- **Entif Glyph Code (EGC)** — universal symbolic representational layer; vendor-agnostic pasigraphy
- **Neo4j** — Pasigraphy Graph store; Concept/Frame/Glyph/Pasigram nodes; HAS_ROLE, EVIDENCE edges
- **PostgreSQL + pgvector** (or SQLite for Phase 0) — Receipts ledger, task/micro-spec schemas, relational event logs
- **Weaviate or pgvector** — vector index for embedding-based similarity search
- **NATS** — pub/sub messaging backbone; intent.received, task.completed event topics
- **MCP Server** — unified tool/data bus; connector plugins; mcp_limitless_pull, etc.
- **LLM Reasoner** (local or cloud fallback) — intent understanding, CoT planning, dynamic decision-making
- **Tiny Reasoning Models (TRMs)** — small specialist models for arithmetic, parsing, code syntax checking
- **ROMA Planner** — hierarchical task decomposition; tree-of-thought assembly of TRMs
- **Cheap-Judge Model** — small/fast first-pass classifier for MoE routing decisions
- **DeepSeek-style OCR / semantic codec** — visual → slugs (high-density latent patch sequences)
- **SentenceTransformer / nomic-embed** — embedding generation for vector index
- **spaCy + NLTK + WordNet + VerbAtlas** — NLP pipeline for Pasigram IR extraction
- **Limitless Pendant API** — audio source; Ambient Parse-Only mode
- **Google ADK** — declarative sequential/parallel/looped agent workflows (optional)
- **Anthropic Claude SDK** — sandboxed sub-agent code execution (Sony/Blink)
- **Playwright / Puppeteer** — headless browser for Browser agent verification
- **Docker** — containerization for Neo4j, Postgres, NATS services
- **n8n** — workflow automation for scheduled triggers and external API integrations
- **LoRA / SMF adapters** — parameter-efficient continual learning for skill modules
- **Petri sandbox** — adversarial simulation environment for alignment testing
- **EntAffirm oracle** — hallucination detection; consistency checking for slow-tier commits

## Conceptual Claims

- All inputs (speech, text, images, code, multi-LLM outputs) can and should be normalized to EGC/pasigraphy graphs before storage
- Receipts are the universal currency of the system: every action (ingestion, reasoning, tool use, self-modification) produces a receipt; receipt absence = failure condition
- Memory must be multi-timescale (fast/mid/slow) with explicit consolidation rules and EntAffirm verification before slow-tier commits
- Reasoning traces are as valuable as factual knowledge and should be stored in ReasoningBank for reuse
- Safety and alignment are first-class architectural concerns, not afterthoughts: EntAffirm, Petri, Tripwire, Genesis Anchor all layer around the core
- Self-modification (Huxley/Gödel Machine) is theoretically possible but only via PR + Petri + EntAffirm gates, never autonomous
- Thin-slice vertical delivery (skateboard → bike → car) is the only viable development modality for a solo developer on this scope
- Research grounding (Nested Learning, Titans, MLACS, SEAL, MONA, etc.) provides mathematical/formal backing for architectural choices
