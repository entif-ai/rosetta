## Summary

Entif v0 is a governed, receipts-first agentic operating substrate. It turns signals (web, repos, docs, internal artifacts) into canonical knowledge objects (Rosetta cognitive tiles), routed through a federated knowledge topology (multiple graphs and indexes), executed via deterministic middleware + policy-gated orchestration, and iteratively improved via measured scoring loops. The document is a deep-research synthesis (not a PRD) covering doctrine, architecture planes, canonical schemas, storage topology, model routing policy, workflow/scoring lifecycle, implementation roadmap, alternatives comparisons, risks, and KPIs. It treats Rosetta as the authoritative spine and defines the first implementation slice as a thin vertical proving the envelope/receipt/routing/deterministic-gating spine.

## Goals And Intent

- Provide a deep-research synthesis of Entif v0 architecture as a stable reference for implementation planning

- Define canonical schemas for execution envelopes, persona contracts, engrams, contributor records, graph-router API, deterministic middleware events, transferability scores, constitutional packs, and receipts
- Compare alternative technology choices (graph DBs, vector stores, orchestration engines, LLM providers)
- Provide an implementation roadmap with phased milestones

## Components And Technologies

- **Execution Envelope**: YAML schema with actor/constitution/request/constraints/tools_allowed/gates/trace; versioned
- **Persona Contract**: YAML schema with identity kernel, cognitive coordinates (0-1 normalized), novelty budget, dissent posture, expression profile, drift metrics with identity_embedding_cid; versioned
- **Engram Record**: JSON schema with source/summary/rosetta_tile_cid/embedding/activation(base_level/decay_d)/associations/ttl_policy/provenance; ACT-R parameterized
- **Contributor Record**: YAML with Pareto classification, watch_config/signals, scores (novelty/reliability/transferability/security_risk/license_friendliness), network/collaborators, provenance/receipts
- **Graph Router API**: JSON request/response with mode/domain/confidence_tier/pattern/context/payload; response targets multiple stores
- **Deterministic Middleware Event**: JSON schema with features (commit_count_8h, contributors_8h, new_repo, stars_delta_24h, license), heuristics (burst_flag, pareto_affinity, voi_estimate), actions_suggested
- **Transferability Score**: YAML with overall/novelty/domain_agnosticism/composability/documentation_quality/reproducibility/security_alignment (0-1); evidence/engrams/receipts/tests fields
- **Constitutional Pack**: YAML with scope_profiles (single_tenant_personal vs multi_tenant_enterprise), policies (tool_use, licensing, safety), signing (RFC8785_JCS, Ed25519 implied)
- **Receipt**: JSON with activity/agent/tool_calls/inputs/outputs/cost/integrity; PROV-compatible (Agent/Activity/Entity)
- **Signal Event**: JSON with event_id/source/subject/features/heuristics/actions_suggested/provenance/receipt_id
- **Compute Hierarchy**: L0–L5 clearance levels referenced in envelope schema
- **Storage**: PostgreSQL+pgvector (relational+vectors), Neo4j or Neptune (property graph), optional Qdrant/Weaviate/Milvus/Pinecone
- **Orchestration**: Temporal (durable workflows) or Argo Workflows (Kubernetes-native DAGs); NATS JetStream for message bus
- **Canonicalization**: RFC 8785 JCS for JSON deterministic serialization
- **Provenance**: PROV-O W3C Recommendation for Entity/Activity/Agent modeling

## Conceptual Claims

- Receipts-first canonicalization: two independent agents producing the same semantic object must converge to the same CID via deterministic canonicalization (RFC 8785 JCS)
- Federated storage: separate knowledge topologies per domain and epistemic tier (GitHub/Research/Product/Org-Policy) reduce blast radius, schema coupling, and ACL complexity
- Determinism before cognition: expensive model inference only after deterministic middleware identifies high-VOI candidates; gates cost and prevents unbounded compute
- Personas as control surfaces: rich personification (novelty, dissent) allowed only under a persona contract with measurable novelty budgets, drift thresholds, and dissent quotas — turning "personification" from vibes into governance
- Federated graph router: every read/write is routed deterministically to the minimal relevant topology based on domain/confidence_tier/TTL/privacy_class/pattern — reducing unnecessary cross-graph joins and blast radius
- ACT-R memory salience: base-level activation provides implementable memory scoring (recency/frequency with decayed traces), enabling principled pruning and tier promotion/demotion
- Workflow scoring: five orthogonal scorecards (Output, Workflow, Capability, Transferability, Persona) make every action measurable, postmortems comparable, and rubric evolution data-driven
- Anti-convergence governance: creativity assistance increasing similarity mandates explicit dissent quotas and anti-convergence rules as first-class artifacts in PersonaForge
- Thin-slice spine proof: v0 slice (GitHub trend → deterministic triage → contributor/repo graph → Rosetta tile → retrieval API) proves envelopes/receipts/routing/state-manifests/TTL-decay/workflow-scoring without building the full system

## Dependencies And Sequencing

- **v0 slice is the first dependency**: all downstream planes (Domain Intelligence, Transferability Scorer, PersonaForge, etc.) depend on the v0 slice proving the envelope/receipt/routing/deterministic-gating spine first
- **Rosetta tile minting**: v0 slice requires Rosetta API integration for tile minting — the spec says Rosetta is the spine but does not define the integration contract (dependency gap — see Finding 24)
- **Constitutions constrain everything**: Constitution Plane (root of admissibility) must be bootstrapped before any other plane can function — no constitution, no envelope validation
- **Deterministic middleware must exist before orchestration escalation**: the escalation chain (deterministic → VOI threshold → impact → policy gate) requires deterministic middleware to be live and calibrated before model routing can work
- **Persona contracts are inputs to execution envelopes**: each envelope's actor field references persona_id; personas must be defined (at least identity_kernel) before envelopes can be instantiated
- **Graph router must be implemented before any federated graph write or read**: all domain writes/reads route through the router — without it, there's no deterministic routing
- **PostgreSQL+pgvector operational baseline required before v0 slice can be tested**: storage is the system-of-record; no storage, no receipts, no engrams, no tiles
- **v0.1 builds on v0**: PersonaForge contracts + council workflow (debate + minority report) + Transferability scorer v1 + license classifier + security gating are all additive to the v0 spine
- **v1 requires all of v0 + v0.1**: multi-graph federation, Muninn memory tiering, richer provenance (PROV mapping), marketplace-ready capability packaging build on the complete v0.1 stack

## Contradictions Or Supersession

- The spec states "Rosetta as the spine" — every transformation produces canonicalized artifacts with strong content-addressing and receipts, and Rosetta is the authoritative data model for minted cognitive tiles. However, the integration contract between Entif v0 and Rosetta (the API endpoint, request/response schemas, tile minting flow) is not defined — the document treats this as already-established but it is not yet specified (see Finding 24)
- The spec states "federated knowledge, not monolith graphs" and includes the "not one graph DB" as a design invariant from transcript context — but the implementation roadmap's v0 slice specifies "contributor registry + repo graph (single graph DB)", which is a single-graph starting point, not federated. The federated architecture is the target but the v0 starting point is not consistent with the doctrine of federation
- The spec references "structured outputs (schema adherence + explicit refusal signaling)" as a recommendation for envelope-adjacent JSON generation — but the execution envelope schema itself is YAML, not JSON, and no Structured Output schema is provided for the envelope generation step. The recommendation exists but no implementation targets it

## Open Questions

- Should the graph router support cross-graph transactions (atomic writes to two graphs) or always use eventual consistency? The spec implies eventual consistency but does not decide.
- The v0 slice uses a single graph DB (Neo4j or Neptune) per the implementation roadmap but the doctrine says "not one graph DB" — does the v0 slice violate the doctrine or represent a deliberate bounded starting point?
- The Engram schema uses `decay_d: 0.5` but ACT-R literature typically uses d in the range 0.2–0.5. Which value is Entif adopting and what is the empirical basis?
- The contributor Pareto classification uses heuristics (commit burst, stars_delta, etc.) but the document does not specify whether Pareto is a binary flag or a continuous score — the schema says `is_pareto: true/false` but discovery_path implies a gradual scoring.
- The spec references "high-signal contributor registry" with trust scores but does not specify whether trust scores are derived from behavior (code review participation, issue response time) or from third-party attestations.
- The Plane map shows bidirectional arrows between some planes (Muninn-inspired Memory Plane ↔ Knowledge Topology Plane; Rosetta Spine Plane → both) — does bidirectional mean the same message contract or are there distinct protocols?
- Anti-convergence rules ("if two agents converge in <2 rounds, force a counterfactual pass") are defined in the dissent_posture but there is no specified mechanism for detecting convergence or triggering the counterfactual pass — is this a manual human-in-the-loop trigger or an automated enforcement?
