## Summary

Berman-prompts.md is a curated collection of 22 generalized system-prompts for building production-grade AI agent systems on OpenClaw. Each prompt template describes a complete, deployable subsystem: Personal CRM, Meeting Intelligence, Knowledge Base (RAG), Content Pipeline, Business Intelligence Council, Security, Cron Jobs, Memory System, Notification Batching, Inbound Sales/Lead Pipeline, Financial Tracking, LLM Usage & Cost Tracking, Logging Infrastructure, LLM Router, Self-Improvement, Backup & Recovery, Agent Prompt File Organization, Dual Prompt Stacks, Data Classification & Privacy Controls, Diagnostic Toolkit, Health Data Pipeline, and Wearable Memory Capture. Section 23 additionally provides a specialized prompt for migrating to the Anthropic Claude Agents SDK with OAuth. The document is a pattern library: each prompt is copy/paste-ready with detailed architecture, database schema, CLI commands, cron job design, and implementation notes. In the context of Rosetta, this document maps existing OpenClaw primitives against the Berman operational model and surfaces 15+ implementation patterns as issue candidates.

## Conceptual Claims

1. **Fire-and-forget logging is viable for production**: The pattern of async, non-blocking log inserts with auto-redaction before storage enables observability without performance degradation — even on hot LLM call paths.

2. **Two-stage content sanitization (deterministic regex + model-based semantic) catches what regex misses**: Deterministic regex handles known injection patterns; a separate model-based scanner handles sophisticated semantic attacks. Fail-closed for high-risk sources (email, URL ingestion).

3. **Conditional prompt loading is a non-negotiable token governance discipline**: Every line in auto-loaded files costs tokens on every request. MEMORY.md is private-only. Skill docs are on-demand. This is not optional optimization — it's production cost control.

4. **LLM smoke test on first call catches credential failures before expensive calls**: A single AUTH_OK canary validates credentials and provider connectivity before any real work starts. Silent failures are eliminated.

5. **Direct security path for content gates must be isolated from agent conversation context**: A separate module that calls provider APIs directly, bypassing the main LLM router, ensures the security scanner cannot be influenced by the agent's own context.

6. **Multi-expert persona council with synthesizer LLM produces better strategic output than single-pass analysis**: Independent expert personas each see only their domain data; parallel execution; synthesizer LLM merges findings into ranked recommendations. The multi-view approach reduces bias.

7. **Pattern learner with auto-approval at threshold (50 decisions) is the right trust calibration for CRM**: Human-in-the-loop for initial decisions; after sufficient signal, switch to auto-add. The threshold is explicit and observable.

8. **Calendar-aware meeting polling outperforms static scheduling**: Poll after meeting end + buffer rather than fixed intervals. Tracks last handled time to prevent duplicates. More accurate and fewer wasted API calls.

9. **Dual prompt stacks with nightly sync review catches drift before it causes behavior divergence**: Claude-optimized vs GPT-optimized formatting; both contain identical operational facts; nightly diff catches "I updated the Telegram topic ID in one stack but forgot the other" class of bugs.

10. **Data classification with context-aware gating prevents Confidential data leakage without requiring the agent to reason about it**: The agent checks message metadata for context type (DM vs group vs external) and automatically skips Confidential data in non-private contexts. This is structural enforcement, not behavioral request.

11. **Exponential backoff on alert frequency prevents alert fatigue without losing critical signals**: State file tracks alert frequency; repeated alerts get exponentially longer suppress intervals. Resets when situation changes.

12. **Hard similarity gate (>40%) for idea deduplication prevents redundant work without blocking edge cases**: Block if similarity exceeds threshold; this is a binary gate not a scoring system. Simple, fast, auditable.

13. **Two-layer LLM safety (writer + reviewer + deterministic gate) is the minimum for high-stakes generation**: Writer LLM personalizes; reviewer LLM validates safety and template compliance; deterministic content gate catches secrets/paths/injection artifacts. Three independent checks.

14. **Encrypted backup with integrity drill validates restore capability before it's needed**: Download + decrypt + manifest parse + checksum validation runs without modifying filesystem. Catches corruption before restore scenario.

15. **OAuth token resolution must error on conflicting credentials (API key + OAuth simultaneously)**: If both ANTHROPIC_API_KEY and CLAUDE_CODE_OAUTH_TOKEN are set, throw error. They conflict in OAuth-only mode. Silent fallback to API key bypasses the intended credential model.

## Dependencies And Sequencing

- **Storage layer first**: All subsystems depend on SQLite WAL mode being established as the standard
- **Security primitives before content**: Prompt injection defense (two-stage sanitizer) and outbound redaction must be wired before any external content ingestion
- **LLM router before LLM-dependent features**: Smoke test, unified router, and direct security path must be operational before lead pipeline, council, or self-improvement councils run
- **Cron infrastructure before cron jobs**: Central log database, PID lock files, and stale cleanup must exist before individual cron jobs are deployed
- **Memory system before self-improvement**: Daily notes and MEMORY.md synthesis pipeline must be established before review councils can draw from it
- **Agent prompt organization before multi-model**: The prompt file structure and conditional loading rules must be in place before dual-stack sync becomes relevant

## Contradictions Or Supersession

- **Berman's OpenClaw uses Gemini embeddings as backend; Rosetta uses pgvector/PostgreSQL**: Berman-PRD specifies `gemini-embedding-001` (768-dim) via OpenClaw builtin memory backend. Rosetta NOT LAME specifies PostgreSQL/pgvector as canonical. The embeddings substrate differs — this is an architectural gap, not a contradiction.

- **Berman uses SQLite WAL for everything; NOT LAME specifies PostgreSQL as canonical registry**: Berman's system is entirely SQLite-based. Rosetta NOT LAME specifies PostgreSQL as canonical with SQLite as local shadow only. This reflects different operational scopes (single-user personal assistant vs multi-tenant sovereign kernel). Berman's SQLite patterns are valid for local/operator context; NOT LAME's PostgreSQL scope applies at the system level.

- **Berman's memory system is file-based (daily notes + MEMORY.md); Rosetta's is multi-plane with PG-backed temporal graph**: Berman's file-based approach is operationally simpler and appropriate for personal use. Rosetta's 5-memory-plane architecture with temporal graph is more sophisticated and suited to multi-tenant sovereign use. The patterns are compatible at different scales.

- **Berman's data classification (§19) classifies "daily notes" as Confidential private-only**: This aligns exactly with Rosetta's memory sovereignty map (Plane 1: truth/provenance, MEMORY.md private-only). No contradiction — reinforces the pattern.

- **Berman's health data pipeline (§21) and wearable memory capture (§22) are low-priority for Rosetta**: These are personal biometric use cases not currently in Rosetta scope. They represent future expansion candidates, not contradictions.
