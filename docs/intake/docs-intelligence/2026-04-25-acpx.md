## Summary

`acpx` is a headless CLI client that wraps ACP-compatible coding agents (Pi, OpenClaw ACP, Codex, Claude Code, Gemini CLI, etc.) behind a unified command surface. It replaces PTY scraping with structured ACP messaging over stdin/stdout. Key capabilities: persistent multi-turn sessions scoped per repo, named parallel sessions, prompt queueing, cooperative cancel, crash reconnect, config files, and NDJSON event streaming. Relevant for Rosetta's agentic tooling strategy: ACP is the protocol layer Rosetta may build on or interop with for coding-agent delegation.

---

## Goals And Intent

- Provide a unified CLI surface for multiple ACP-compatible coding agents
- Replace fragile PTY scraping with structured protocol communication
- Support persistent multi-turn sessions with crash resilience
- Enable parallel workstreams via named sessions
- Offer fire-and-forget queuing with cooperative cancel
- Formalize config file hierarchy (global + project-level)

## Components And Technologies

- **acpx CLI** — unified command surface wrapping multiple ACP-compatible agents
- **ACP (Agent Client Protocol)** — structured protocol for agent-to-agent communication over stdin/stdout (agentclientprotocol.com)
- **ACP adapters** — per-agent wrappers (pi-acp, codex-acp, claude-agent-acp, etc.); auto-downloaded via npx
- **Session state** — stored in `~/.acpx/sessions/`; includes metadata, history previews, closed flag
- **Config files** — `~/.acpx/config.json` (global) + `<cwd>/.acpxrc.json` (project); JSON schema with keys for defaultAgent, defaultPermissions, nonInteractivePermissions, authPolicy, ttl, timeout, format, agents, auth
- **NDJSON streaming** — structured event output with envelope: eventVersion, sessionId, requestId, seq, stream, type
- **Permission system** — `--approve-all`, `--approve-reads` (default), `--deny-all`, `--non-interactive-permissions fail|deny`
- **Queue/IPC system** — cooperative cancel via `session/cancel` ACP message; queue owner TTL management
- **Crash recovery** — pid monitoring, agent respawn, `session/load` → `session/new` fallback chain

## Conceptual Claims

- ACP replaces PTY scraping as the preferred agent-communication mechanism
- Structured ACP messages (thinking, tool_calls, diffs) are more reliable than ANSI stream parsing
- Directory-walk session routing reduces explicit session management burden for users
- Named parallel sessions enable multi-workstream agent orchestration in a single repo
- Soft-close preserves session history for audit/replay while freeing process resources
- Crash reconnect with `session/load` provides continuity across agent process restarts
- Config file hierarchy enables project-specific overrides without global side effects

## Dependencies And Sequencing

- **External dependency chain:** Node.js → npm → acpx → (ACP adapter per agent) → underlying coding agent runtime
- **Adapter auto-download:** acpx auto-downloads ACP adapters via npx on first use; no manual `npm install` of adapter packages required
- **Agent prerequisites:** User must separately install the underlying coding agent (Pi, Codex CLI, Claude Code CLI, etc.); acpx does not bundle agents
- **Config resolution order:** global `~/.acpx/config.json` → project `<cwd>/.acpxrc.json` → CLI flags (CLI wins)
- **Session routing:** requires git root for directory-walk; falls back to exact cwd match in non-git directories
- **JSON output dependency:** `--json-strict` requires `--format json`; guarded in CLI
