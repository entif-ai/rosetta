## Summary

A conversation between Crates (Entif architect) and a ChatGPT Emilie about three converging topics: (1) unexpectedly high AI API bills from manual UI queries — and how provider caching economics actually work, (2) a proposed enterprise shared cache architecture keyed by git blob hash + ABAC/RBAC policy domains, with activity-based TTL and per-tenant/per-engagement isolation, and (3) integration of AuthZ/AuthN/RBAC into Rosetta's tile spine via an IAM StdPack (`iam.principal`, `iam.delegation`, `iam.cache_domain`, `iam.decision`) that snaps onto Rosetta's existing `rosetta.run → action → toolcall → observation → evaluation` trace with signed receipts. The conversation culminates in a concrete `iam.decision` tile schema proposal (Option A via receipt subtype, or Option B via new StdPack tile kind) plus three sibling tiles for principal identity, delegation chains, and cache security domains — all aligned with Rosetta v3.0.0 Core Spine Specification. A final section proposes semantic slugs (authz slugs, context CIDs, cache domain slugs) as a negotiation protocol to avoid resending large payloads and to detect stale authorization state cheaply.

## Goals And Intent

- Understand why AI Studio/UI usage generates unexpectedly high bills (context accumulation, long-context tier pricing)
- Understand provider implicit vs explicit caching mechanics and their economics
- Design an authorization-aware shared cache architecture for enterprise multi-agent/multi-engineer scenarios
- Extend Rosetta's IAM/AuthZ vocabulary via a StdPack without bloating core
- Define the Guard micro-spine pattern as a normative trace (action → decision → receipt → toolcall → observation → receipt → evaluation)
- Propose semantic slugs as a lightweight negotiation protocol for capability state and context block exchange

## Components And Technologies

- **Vertex implicit/explicit context caching** — $4.5/Mtok-hour storage rent; $0.2–0.4/Mtok cached input; 90% discount vs normal input
- **Gemini 3 Pro tiered pricing** — $2/Mtok (≤200K tokens), $4/Mtok (>200K tokens); long-context doubles input cost
- **Anthropic cache_control** — opt-in; 5-min default lifetime; 1-hour paid option; KV + hash storage
- **OpenAI prompt caching** — automatic on prompts >1024 tokens; cached in 128-token increments; usage.cached_tokens
- **Git blob hash** — primary cache key for code artifacts; automatic cross-branch deduplication
- **SHA-256 content addressing** — for block_id, tapestry_cid, authz_slug computation
- **JWT/macaroons-style capability tickets** — portable short-lived authorization artifacts
- **Bloom filters / Merkle trees** — large manifest negotiation at scale
- **ROCK-3005-IAM StdPack** — iam.principal, iam.delegation, iam.cache_domain, iam.decision tile kinds
- **Rosetta v3.0.0 Core Spine** — Run → Action → ToolCall → Observation → Evaluation + Policy + Receipt + Incident Envelope
- **rosetta.tapestry** — compiled context bundle for sharing; cached prefix = tapestry with CID
- **Guard micro-spine** — action → iam.decision → receipt → toolcall → observation → receipt → evaluation (normative trace)
- **Activity-based TTL** — sliding TTL reset on reuse; expire on inactivity; prevents $108/day storage bleed

## Conceptual Claims

- UI-based AI Studio usage generates high bills because accumulated conversation history is resent on every turn, silently crossing the 200K token long-context pricing threshold
- Implicit caching is probabilistic and visibility-poor without metadata inspection; explicit caching has storage rent that requires strict TTL management or it becomes a cost bleed
- Break-even for explicit caching requires only ~2 reuses within 10 minutes at Gemini 3 Pro long-context pricing to outperform raw token cost
- Git blob hash as cache key automatically deduplicates across all branches and engineers sharing the same file content, eliminating branch-specific bookkeeping
- Authorization-aware shared cache is viable only when keyed by (tenant × classification × ABAC × vendor route) as a cache security domain; cross-domain reuse is forbidden unless explicitly PUBLIC_CORPUS designated
- Cache side-channel leakage (latency, error differences, metadata exposure) must be mitigated by never exposing cache-hit status to end users, normalizing latency, and keeping cache indices server-side
- Entif's existing Guard Layer concept and Genesis Protocol authority structure already provide the governance primitives needed for cache orchestration; the delta is treating "Context Cache" as a first-class governed resource
- Rosetta v3.0.0's tile spine (Run → Action → ToolCall → Observation → Evaluation + Receipt + Policy) directly accommodates the IAM decision and audit model; IAM tiles extend via StdPack rather than bloating core
- The Guard micro-spine (action → iam.decision → receipt → toolcall → observation → receipt → evaluation) is the normative trace for all side-effect-producing operations and should be codified in Rosetta Profiles
- Semantic slugs (authz_slug, block_cid/tapestry_cid, cache_domain_slug) enable lightweight negotiation protocols that prevent wasted attempts and avoid resending large payloads via manifest+diff exchange
- AuthZ slug + capability ticket pattern allows clients to preflight permission state cheaply and receive fast rejection on mismatch, improving overall system efficiency
- Cache orchestration MVP should prioritize: (1) AuthZ slug preflight, (2) Tapestry CID manifest + diff protocol — before investing in Bloom/Merkle sophistication or mesh replication
