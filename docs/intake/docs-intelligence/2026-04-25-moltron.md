## Summary

Moltron is an OpenClaw skill-building system that transforms fragile `SKILL.md` text files into executable, versioned, self-measuring SmythOS workflows. It adds an evolutionary loop — self-assessment, auto-repair, telemetry, scoring — so agents harden skills over time rather than reinventing wheel per session. The system is positioned as an "evolution engine" enabling swarm-scale specialization and deployment. Entirely open standards-based (CLI, OpenTelemetry, Git, SmythOS), MIT-licensed, and cross-platform (OpenClaw, Cursor, Claude Code, OpenAI Codex).

---

## Goals And Intent

- Solve OpenClaw's #1 obstacle: skills are fragile text files, not executable artifacts
- Enable agents to self-reflect, measure performance, and learn over time
- Achieve "infinite evolution" — a digital employee that becomes expert and improves daily
- Enable swarm-scale deployment: build one expert agent, clone skills to 50 others
- Replace expensive single-model execution with specialized model routing per step
- Provide telemetry, audit logs, and flight-recorder root access visibility

## Conceptual Claims

1. Text-file skills (current OpenClaw SKILL.md) are fundamentally insufficient: fragile, blind, amnesiac.
2. Self-improving agents are achievable via an evolutionary loop: goal → fail → build → test → repair → crystallize → execute → score → repeat.
3. Skill compilation to executable workflows (SmythOS) is superior to skill interpretation as prose.
4. Specialized model routing (expensive for evolution, cheap for execution) is the correct economic model.
5. Telemetry and flight-recorder auditability is a prerequisite for safe root-access agent operations.
6. Skill folders can be cloned across agents to achieve instant expertise replication (swarm scale).
7. Open standards enable cross-platform skill portability (OpenClaw, Cursor, Claude Code, Codex).
8. "Zero config, works out of the box" is achievable for skill self-improvement systems.

## Dependencies And Sequencing

- **Dependency on SmythOS:** Skill compilation requires SmythOS runtime; if SmythOS becomes unavailable, Moltron's core value proposition degrades significantly.
- **Dependency on OpenTelemetry ecosystem:** Telemetry layer, scoring, and auto-repair triggering all depend on OTel instrumentation.
- **Dependency on Git:** Versioning and backup require Git presence in environment.
- **GitHub dependency:** Install script sourced from `raw.githubusercontent.com/adridder/moltron/main/install.sh` — if repo goes down, install path breaks.
- **Install sequence:** Must inject `moltron-skill-creator` into `~/.openclaw/workspace/skills/` before OpenClaw restart to trigger initialization.
- **Chat trigger required:** `@moltron init` must be sent in OpenClaw chat after installation — not fully automated.
- **Cross-platform claim untested:** Document asserts compatibility with Cursor, Claude Code, Codex but provides no evidence of testing or configuration for those platforms.

---

## Contradictions Or Supersession

- **Contradiction: "Zero config and works out of the box" vs. multi-step install with chat trigger.** The document claims zero config and works out of the box, but requires: (1) curl install, (2) copying skill creator to specific path, (3) OpenClaw restart, (4) sending `@moltron init` message in chat. This is multi-step and requires specific sequencing. "Zero config" appears marketing-optimistic.
- **Supersession:** Moltron explicitly positions itself as superseding current OpenClaw SKILL.md approach. Current skills are characterized as "just text files" that are "fragile, blind, amnesiac." Moltron claims to replace this with executable, versioned, scored workflows.
- **Unverified cross-platform claims:** Assertion that it "also works with Cursor, Claude Code, OpenAI Codex" has no evidence in this document. Should be treated as aspirational until verified.
