## Summary

Document the known gap between the MVP's JCS implementation (Node built-ins / JSON.stringify) and full RFC 8785 compliance. Track as a non-blocking known issue with a clear upgrade path.

## Problem Statement

The MVP canonicalizer uses Node built-ins (JSON.stringify) as a shortcut. RFC 8785 specifies precise rules for canonical JSON (key ordering, no trailing commas, Unicode escaping, number formatting, etc.) that JSON.stringify does not fully enforce. This is a known compliance gap that must not block MVP but must be tracked for later resolution.

## Proposed Implementation

### Documentation artifact

Create `docs/specs/rosetta-canonicalization.md` (or add to existing canonicalization spec) with:

1. **Current state**: MVP uses `JSON.stringify` for canonicalization. This is sufficient for local development and test vectors but does not guarantee RFC 8785 compliance.
2. **Gap analysis**: List which RFC 8785 rules JSON.stringify satisfies and which it violates (e.g., number formatting for values like `1.0` vs `1`, Unicode escaping, etc.)
3. **Upgrade path**: When RFC 8785 compliance is required (RRP-Auditor tier, production deployment), migrate to a standards-compliant library (e.g., `canonicalize` npm package, or a hand-rolled implementation)
4. **Test vector guidance**: TV1 test vectors were generated by the MVP implementation — they are self-consistent but may not be RFC 8785-generally valid

### Tracking label

Add `jcs-compliance-gap` to the issue and to any related code comments.
