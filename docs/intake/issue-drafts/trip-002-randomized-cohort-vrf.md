## Problem Statement

Fixed validator committees are susceptible to collusion,Bias, fatigue, and political capture. Each tripwire escalation should be reviewed by a unique, unpredictable cohort selected at random — like jury duty for digital ethics. Selection must be cryptographically provable so no administrator can manipulate the outcome.

## Proposed Solution

### Verifiable Random Function (VRF) Based Selection

For each tripwire event:
1. Sortition seed = `VRF(tripwire_hash + event_timestamp + poolepoch)`
2. VRF proof generated by poolregistry
3. Verifiable by any third party — no one can bias the seed
4. Cohort size N selected from eligible pool after filtering

### Eligibility Filtering (Before Randomization)

- `is_active == true`
- `qualification_score >= 80`
- Not recently selected (prevent same validator dominating)
- Geo/cultural diversity constraints if configured
- Domain filter (e.g., suicide-prevention specialists get weighted selection for mental-health events)

### Backup Cohort Pattern

Each event assigns:
- **Primary cohort**: N validators
- **Backup cohort**: M validators (activate if primary quorum not reached in timeout)

Timeout on primary = 5 minutes (configurable). Backup pool activated automatically.

### Cryptographic Provability

Use VRF (Elliptic Curve VRF — BN128 or Ed25519) to generate deterministic but unpredictable selection seed. VRF proofs are on-chain or registry-attested so outcomes can be independently verified.

## Implementation Notes

- **Location**: `src/ethics/tripwire/selection.mjs`
- **VRF library**: `circomlib` (for BN128 VRF) or `ristretto255-vrf` (for Ed25519)
- **Selection algorithm**: ChaCha20-based weighted shuffle after VRF seed injection
- **Pool size minimum**: 20 eligible validators required for statistically meaningful randomization
- **Diversity filtering**: Optional geo/cultural bucketing before final selection

## Acceptance Criteria

1. Same seed + same pool + same epoch always produces identical cohort (deterministic reproducibility)
2. No party can predict outcome before selection is committed (unforgeability)
3. VRF proof is verifiable by independent third party
4. Backup cohort activates within timeout if primary quorum not reached
5. Validator burnout tracking: no validator assigned more than 5 events/day without cooldown
6. Unit tests: deterministic repro, unpredictability, backup activation, diversity filtering

## Dependencies

- TRIP-001 (escalation envelope format must be defined first)

## Risks

- **Pool too small**: VRF selection is meaningless if pool < 20; fallback to fixed committee required until pool grows
- **VRF implementation complexity**: Use existing library, don't roll own crypto
